# Aura 0.1.0

The first release of Aura, Aurora Silicon's Apple Silicon bootloader and experimentation environment, derived from Asahi Linux's m1n1.

## Origin

The initial fork is based on m1n1 **v1.6.1 plus 27 commits**, at [`b4654b32941d`](https://github.com/AsahiLinux/m1n1/commit/b4654b32941d51afdb77579d63e7cb1aa6c03ecc). Subsequent upstream integration reaches [`c42cf43d0388`](https://github.com/AsahiLinux/m1n1/commit/c42cf43d03887208e70ec5dcc4da0b2af3699c54), **v1.6.1 plus 50 commits**. The Aurora version starts separately at 0.1.0.

## Changes since the fork

### MacBook Neo / A18 Pro (T8140, J700)

- Native boot work covering firmware version detection, ADT memory geometry, firmware read-only mappings and reservations, and inherited internal display scanout.
- Secondary CPU bring-up through verified RAM vectors, bounded calls and waits, WFE parking, and a complete-CPU-set check before Linux handoff. Export the unsafe-WFI CPU policy for the kernel.
- Firmware-controlled system cache handling, validated PMGR power topology, scoped DAPF programming, guarded locked-register diagnostics, and failure propagation before handoff.
- Post-M4 NVMe/ANS adoption without stopping or resetting the live coprocessor. Forward explicit adoption state across chainloads; validate register apertures and inherited queues; block retries or handoff after incomplete setup and commands.
- GPT validation, bounded cached storage reads, contiguous FAT file loading, explicit small-FAT32 support, file-buffer ownership and cleanup, and checked gzip/DTB bounds. Route `boot=` and the storage proxy opcode through the common Linux handoff; allow EFI payloads to supply their initramfs.
- Bounded Stage 1 host windows and configuration paths, separate ESP Stage 2 builds, runtime USB transport selection, and explicit debug/proxy boot options.
- SPMI transport for USB-C controllers, bounded HPM commands, eUSB2 repeater readiness, ATC PHY setup, USB Gen1 CDC descriptors, chained transfers, EP0/reset recovery, disconnect recovery, and verified proxy-client reconnects.
- Initial validated T8140 PCIe bring-up, Wi-Fi identity handoff, speaker-safety provenance, AVE firmware reservations/CRCs, GPU OPP/UAT reservations, ISP power sequencing/heap export, and bounded DisplayPort tuning handoff. These are boot and firmware handoff changes; they do not establish complete OS support for each device.

### M5 (T8142, J813)

- Initial native FDT boot and KIS RAM loading.
- Bring up all ten CPUs and initialize cluster performance states with corrected frequencies from J813 measurements.
- Hand off runtime ATC PHY and USB4 tuning and preserve live display firmware mappings for Linux.

### M6 (T8152, J873g)

- Conservative KIS/FDT boot bring-up, all twelve CPUs through PMGR2, and explicit firmware performance requests.
- Guarded USB-C DisplayPort setup, retained framebuffer allocations, high-IOVA framebuffer support, and the normal boot console.
- Record the previously qualified visible USB-C Linux console handoff. The exact 0.1.0 build remains a separate hardware-test candidate.

### Shared fixes and project changes

- Preserve iBoot's warm SEP registration on M2 and newer chips, and forward `apfs-preboot-uuid` from ADT into FDT `/chosen`.
- Preserve inherited DART translation tables and correct T8110 TLB polling and contiguous mapping lookup.
- Harden RTKit allocation alignment, ownership, firmware-supplied translations, failed replies, SART unmap reporting, and bounded power transitions.
- Validate Rust ADT spans and full property lengths, import full FDT validation, bound firmware-version parsing, validate firmware reservations, and propagate proxy/cache/SMP errors.
- Keep DockChannel output best effort and startup notices atomic. Add legacy boot-path replay and release/install tooling and regression coverage.
- Establish Aura's name, Aurora logo, repository and packaging identity, contribution provenance, and licensing boundary. Inherited code retains its licenses; Aurora contributions use GPL-2.0-only. Preserve third-party attribution and the separate FatFs source dependency.
- Fix the freestanding release link by bounding Rust register-path scanning, including full eight-node paths; fix native AArch64 Clang target selection, normalize C formatting and repair CI tooling.
- Add version-tagged artifacts, matching debug symbols, build manifests, SHA-256 checksums, and automatic **draft** GitHub releases.

## Additions in the refreshed 0.1.0 draft

Imported the [requested m1n1 comparison](https://github.com/aurora-silicon/m1n1/compare/bf75ce31fee4...f3ac615eb137) through `f3ac615eb137`, together with the two missing startup/runtime-USB prerequisites:

- Accept an inherited external DCP that is started and stopped in its idle loop, while retaining mailbox checks and the stricter internal-DCP rule. Preserve the internal display if only the external handoff fails.
- Publish external display DMA, mailbox and power suppliers together, with bounded dependency traversal and rollback. On refusal, withdraw owned routes, controller/PIODMA IOMMU references and suppliers; retain internal and unrelated resources, reject ambiguous ownership and malformed topology, and validate aliases before following them.
- Export bounded translated external-register and mapper-cell metadata for diagnosis. Retain optional firmware-provided T8130 common CIO shim tuning through the existing bounded decoder.
- Keep DCP iBoot payload storage in fixed transport buffers without flexible header members; preserve wire layouts and response bounds. Remove unused Rust imports/feature gates for strict builds.
- Disable J700's internal Touch ID SPI controller when the firmware ADT omits it, without inferring a sensor from an external keyboard or changing other machines.
- Carry High-Speed and SuperSpeed USB engines in one image and choose at runtime. Remove the former Neo-specific build profiles. Configured Stage 1 boot has no implicit proxy wait; `aura-debug`, `aura-proxy`, and an explicitly configured interception window retain development access.
- Add real-libfdt ownership, rollback, malformed-reference, alias, supplier and Touch ID fixtures; independent DCP wire checks; and runtime USB/startup coverage. Keep the ISP fixture extraction scoped to its production helper after the new Touch ID helper was added.

This refresh establishes source integration and build/host validation, not external-display hardware qualification or completed Touch ID support.

## Artifacts

- `aura-v0.1.0-stage1.zip`: raw `aura.bin` and RAM-loadable `aura.macho`, embedded Stage 1 configuration, build metadata, licenses, and checksums.
- `aura-v0.1.0-stage2.zip`: the corresponding `ESP_STAGE2=1` images, omitting the Stage 1 configuration block.
- Matching `*-debug.zip` archives contain both ELF images and debug symbols.
- `SHA256SUMS` checks the downloadable archives. GitHub's source archive identifies the tagged source.

These are separate bootloader components, not an assembled Aura + DTB + U-Boot UEFI `boot.bin`. Match the board and firmware when assembling an installation bundle. Both stages now include runtime USB transport selection; explicit debug/proxy controls are documented in `docs/boot-options.md`.

## Qualification and remaining work

Release builds and host/CI checks do not establish a new hardware qualification. These exact 0.1.0 artifacts have not been boot-tested on hardware. Device and firmware paths retain their documented limits. Mach-O/SPTM/native-SSD feature development retained in `aura-internal` is outside this release.
